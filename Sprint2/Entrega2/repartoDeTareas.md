# Reparto de tareas

En este sprint, solventando los problemas del sprint 1, hemos creado una división de tareas mucho más ajustada, con tamaños más realistas.

Esto se puede ver en el github project asociado más claramente, junto a la distribución de tareas a cada miembro, donde hemos priorizado que la carga de trabajo sea equitativa para todos.

Un punto que aún no hemos hecho es basar las tareas en historias de usuario, esto debido a que el product backlog se ha hecho este sprint.
